# Architecture file map

Each numbered SQL file is called by the migration runner/administrator and imports no application libraries. Inputs are DDL plus existing tables; outputs are objects/seed rows below. No external APIs are called. Callees are the referenced database tables and functions. Removing a file breaks its definitions and dependent objects. Failures include missing extensions, FK/constraint violations, permissions and duplicate policies.

## Other files

AGENTS.md controls all agent work; .gitignore excludes common secrets/archives. Removing them weakens workflow safeguards. apply_all.sql is the alternative combined bootstrap, consumes every numbered migration and must be generated consistently. It calls no external services.

All docs are read by developers/operators, import no code, call no APIs and change no tables. Missing/stale documentation causes incorrect recovery or implementation assumptions. MASTER_IMPLEMENTATION_PROMPT.md is the accepted scope; APPROVED_ENTITIES.txt is the exact 77-name test oracle; MASTER_DATABASE_SPECIFICATION.md describes the original schema; IMPLEMENTATION_AUDIT.md records defects and dependencies; IMPLEMENTATION_STATUS.md tracks phase gates; PROGRESS_REPORT.md records checkpoint/recovery; STOP_AND_SAVE_PROTOCOL.md governs persistence; DATA_SOURCES.md distinguishes registrations from integrations; API_MAP.md records pending endpoints; ML_PIPELINE.md defines honest training requirements; DEPLOYMENT.md documents the production gate; ARCHITECTURE_FILE_MAP.md is this inventory.

## Dependency flow

Database -> backend -> ingestion -> agriculture -> features -> ML -> optimization -> recommendations -> frontend. Only SQL definitions exist at the audit checkpoint. There are no application imports/callers or runtime external API calls yet.
